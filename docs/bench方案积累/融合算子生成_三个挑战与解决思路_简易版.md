# 融合算子生成：三个难点（简易版）

## 1. 合在一起，未必更快

**难点：** 不同计算需要不同的分块和资源。硬合在一起，可能省了数据搬运，却增加等待、降低并行度。

**为什么光调参不够：** 融合方案选错了，继续调参数也可能收效很小。

**我们怎么做：** 保留多种融合方案，结合硬件选择起点，再用实测决定继续还是换方向。

## 2. 合在一起，还得重新确认算得对

**难点：** 融合改变计算顺序和数据使用时机。有些错误只在特殊输入或连续调用时出现。

**为什么普通测试不够：** 单个算子通过、几个样例通过，不能代表融合后的整个计算都正确。

**我们怎么做：** 测完整结果、测连续调用，并把报告绑定到代码版本，避免拿旧成绩证明新代码正确。

## 3. 知道变慢了，还得判断怎么改

**难点：** 同一方案可能让多数输入变快、少数变慢。只看平均成绩，分不清该调分块，还是换融合方案。

**为什么有反馈还不够：** 成绩说明效果，却不会直接告诉我们下一步该改哪里。

**我们怎么做：** 看每个 case 的瓶颈和历轮变化，再决定局部修改、换方案或请人指导，最后保留最佳已验证版本。

已有方法也能融合；我们的重点是把上述判断做得更有依据，效果需要实验验证。第二点目前是正确性保障，还不是新的验证算法。
