# 融合与资源权衡：两篇论文的用途

2026-09-25。这两篇不属于用户指定的两个课题组，补充它们是为了给“融合为什么难”提供直接研究融合的证据。页码均为下载 PDF 的文件页码。

## 1. Welder：局部最快不等于融合后最快

- **论文：** *Welder: Scheduling Deep Learning Memory Access via Tile-graph*，OSDI 2023，正式论文 701–718 页；下载文件含封面，共 19 页。
- **文件：** [01_Welder_OSDI2023.pdf](01_Welder_OSDI2023.pdf)。[会议与下载来源](https://www.usenix.org/conference/osdi23/presentation/shi)。
- **重点：** PDF 第 4 页，§2、图 2；第 5–7 页，§3 的 tile-graph 与调度。
- **核心证据：** Matmul 和 Softmax 单独优化时偏好的分块分别为 `[32×64]` 和 `[4×128]`，无法直接在共享内存中复用中间结果。采用共同分块 `[16×128]` 后，两者单独运行分别退步约 15% 和 4%，整体耗时却从 0.36 ms 降至 0.29 ms。此数值来自论文示例，不是本项目实验。
- **为什么相关：** 融合要同时权衡算子内部复用和算子之间复用；逐个调到最快再拼起来，可能错过整体更优方案。
- **对方已经解决什么：** 用 tile-graph、分块传播、分层存储和流量代价模型组织联合优化。因此不能说现有工作完全没有考虑融合联合决策；本项目也没有实现相同的形式化调度搜索。

## 2. FusionStitching：省搬运可能以损失并行为代价

- **论文：** *FusionStitching: Boosting Memory Intensive Computations for Deep Learning Workloads*，arXiv:2009.10924，2020 首稿、2021 v2。此下载版本是预印本，不标为 ASPLOS；AStitch 是相关的另一篇工作。
- **文件：** [02_FusionStitching_arXiv2021v2.pdf](02_FusionStitching_arXiv2021v2.pdf)，14 页。[原文与版本](https://arxiv.org/abs/2009.10924v2)。
- **重点：** PDF 第 3 页 §2.3；第 4–6 页 §3.2、§4.1–4.4。
- **核心证据：** 复用中间数据需要线程间通信并占用片上存储，可能降低并行度。归约若为了向下游直接传值而被限制在一个线程块内，可能不如拆开后由多个线程块协作，即使拆开增加了启动和片外搬运。
- **为什么相关：** 融合收益不随融合程度单调增加；性能变差时需要区分通信、存储和并行的冲突，不能只追求更少的 kernel。
- **对方已经解决什么：** 使用多种组合方式、调度候选及两级代价模型搜索融合方案。论文对 XLA/TVM 的评价对应当时版本，不能直接当作 2026 年这些系统的现状。

## 与主文的关系

两篇共同支撑挑战一“融合边界与执行方式互相制约”，并解释挑战三中为什么不同输入、不同资源条件下的收益可能冲突。**根据这些机制提出跨 case、跨轮审查，是我们的研究思路；论文没有直接证明本项目的审查机制优于其他 Agent。**
